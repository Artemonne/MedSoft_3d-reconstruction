## B. Обязательные unit-тесты

1. Тест `HU = slope * stored + intercept`: например, для `stored=1024`, `slope=1`, `intercept=-1024` ожидается `0 HU`; для `stored=1424` ожидается `400 HU`.
2. Маска `>= 400`: `[-1000, -120, 0, 40, 399, 400, 1000]` -> `[False, False, False, False, False, True, True]`.
3. Сортировка срезов по физической позиции при специально перепутанных именах/InstanceNumber.
4. Объём с `(slice=2.5 мм, row=0.7 мм, col=0.8 мм)` должен сохранять анизотропность, в том числе при экспорте.
5. Различать `SliceThickness=5 мм` и фактический шаг между срезами `2 мм`.
6. Отдельные seriesUID не объединяются; пустой/битый файл не крашит приложение.
7. Отсутствующие необязательные теги корректно обрабатываются.
8. Region Growing: переход между 6-соседями при `abs(HU(q)-HU(p)) <= tolerance_HU`, валидный seed, отсутствие выхода за границы. Отдельные фикстуры для разных компонент/seed и изменения tolerance; смена seed внутри одной компоненты может не менять результат. Отрицательная/NaN tolerance и seed в padding отвергаются.
9. Marching Cubes на шаре/кубе формирует сетку с конечными координатами и валидными индексами треугольников.
10. STL повторно читается, число треугольников совпадает, координаты/bounds совпадают с активной сеткой в пределах `atol=0.001 мм, rtol=1e-5`. Число вершин не обязано совпадать: STL не хранит общие индексированные вершины. Чтение тем же VTK — round-trip, независимое доказательство — внешний редактор; отдельную библиотеку только ради дублирования чтения не добавлять.
11. Тест surface smoothing/decimation проверяет изменение и сохранение базовой геометрии; repair проверяет не только факт вызова функции, но и свойства сетки после операции.

### Измеримые проверки поверхности (инженерные критерии)

- Использовать плотный фантом радиусом 10 мм с контролируемым шумом. Для выбранных параметров smoothing вершины меняются, нет новых boundary/non-manifold edges, относительное изменение объёма <=5%, максимальное двустороннее расстояние до исходной поверхности <=0.5 мм. Для открытой сетки не оценивать объём как надёжную метрику.
- Для decimation на подходящем плотном фантоме цель — удалить 50% граней, допустимо отклонение 5 процентных пунктов; та же проверка расстояния/объёма и топологии. На произвольной модели ограничение сохранения топологии может не позволить достичь цели: показывать фактическую долю, не выдавать её за запрошенную.
- Для repair удалить треугольники из небольшой области закрытого фантома; до ремонта boundary edges >0, после закрытия тестовой дыры =0, non-manifold edges =0. Отдельно добавить отсоединённый фрагмент: удалить именно выбранный фрагмент и сохранить контрольную основную поверхность. Сохранение всех анатомических компонент — поведение по умолчанию.
- Для преобразования координат проверять известные точки с погрешностью <=0.001 мм. Геометрические bounds поверхности Marching Cubes проверять по аналитике/эталонной маске с учётом половины вокселя и линейной интерполяции у углов; не требовать точного совпадения с границами объёмного рендера.
- Для T28 фиксированный пример вдоль x: `[0,4,8,30] HU`, seed в первом вокселе, tolerance=4 даёт первые три вокселя, tolerance=3 — только первый. Это отличает локальный перепад от сравнения только с HU(seed). Диагональные касания при 6-связности не соединяют компоненты.
- В T28 добавить путь обхода: воксель, отклонённый от одного соседа из-за большого перепада, должен приниматься позже через другой допустимый путь. Перестановка порядка соседей не меняет итоговую область.

Пороговые значения этих проверок выбраны проектом для воспроизводимых фантомов, не являются медицинскими нормативами и не приписываются преподавателю.

## C. Ручные сценарии для сдачи

Сценарий 1 (15 баллов): открыть валидную серию -> метаданные -> HU=200 -> осмотреть 3D -> HU=400 -> убедиться в изменении -> повернуть 3D.

Сценарий 2 (+5): открыть 2D-срез -> кликнуть seed -> выбрать Region Growing -> выставить tolerance -> 3D -> изменить tolerance -> пересчёт.

Сценарий 3 (+3): переключиться на построение Marching Cubes -> явно показать триангулированную поверхность, вращение.

Сценарий 4 (+4): выполнить smoothing, decimation, repair, показать сетку до/после и метрики. Если на конкретной модели дефектов для repair нет — использовать контролируемый тестовый дефект.

Сценарий 5 (+3): экспортировать STL -> открыть через Blender / MeshLab / другой редактор -> убедиться в геометрии и пропорциях. Преподаватель будет пользоваться своим 3D-редактором; файл должен быть стандартным.

Сценарий 6 (устойчивость): другая CT-серия -> отсутствующие поля пациента -> ошибка неподдерживаемого файла без падения.

Сценарий 7 (актуальность): построить и обработать mesh -> изменить HU -> дождаться новой маски -> убедиться в сбросе обработки -> заново построить поверхность -> экспортировать именно её. На этапе 1 отдельно проверить отображение бинарной маски без Marching Cubes.

## D. Quality gates

**Gate 0 — аудит без кода:** задание и лекция сверены, R01–R14 трассированы, исправления и риски записаны в `06_stage0_audit.md`, diff сохранён. Установка приложения и его тесты ещё не требуются и не объявляются пройденными.

**Gate 1 — этап 1, обязательные 15:** сначала T30 и воспроизводимая установка; затем T01–T11, T19–T25 в части загрузки/HU/геометрии, T26–T27 для базового сценария. Две независимые реальные серии через GUI, включая отсутствие необязательных метатегов; бинарная маска вращается и пересчитывается без зависимости от Marching Cubes. Неподдерживаемые валидные CT — известные ограничения, а не PASS по универсальности R10.

**Gate 2 — этап 2, дополнительные алгоритмы (+8):** T12–T15, T23, T28, применимые T24/T26/T27 и регрессия этапа 1; seed реально выбирается пользователем; чувствительность следует описанному критерию; маска и отдельная треугольная поверхность доступны в GUI.

**Gate 3 — этап 3, обработка/экспорт (+7):** T16–T18, T23, T26, T29 и регрессия; все три операции поверхности доказаны метриками и GUI, файл вручную открыт внешним редактором с проверкой размеров в мм.

**Gate 4 — этап 4, финальная приёмка:** весь pytest, T01–T30 в применимых конфигурациях, повторный T30 в чистом venv, минимум две реальные серии, внешний редактор и offline-сценарий. Фактические результаты в `docs/TEST_RESULTS.md`; PASS / FAIL / NOT TESTED отдельно для автоматической и ручной частей. Пропуски и неподдерживаемые варианты не превращать в PASS. Готовность к 30 баллам — только при доказательствах всех R01–R14; итоговую оценку выставляет преподаватель.
