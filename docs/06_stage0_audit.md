## C. Противоречия и основные риски

| Риск / прежняя неоднозначность | Возможное последствие | Исправление / что остаётся сделать |
|---|---|---|
| Основной viewer всегда строится через MC, но MC отложен до этапа 2 | Этап 1 нельзя принять самостоятельно | Введён базовый объёмный показ бинарной маски; MC — отдельный режим этапа 2 |
| InstanceNumber как fallback без геометрии | Правдоподобная картинка с выдуманными расстояниями/осями | Только диагностический список; без IOP/IPP реконструкция блокируется |
| «Произвольная валидная серия» при неподдержанном Enhanced CT, shear или сжатии | Отказ на файлах преподавателя, риск обязательных 15 | Ограничение названо честно, профиль синтаксисов проверяется; расширять при необходимости до сдачи. Дружелюбная ошибка не равна выполнению R10 |
| CT или apply_modality_lut автоматически означают HU | Порог применяется к неверным единицам; LUT без тегов возвращает вход без изменений | Проверять правила CT/единицы, коэффициенты каждого среза, padding и signed/unsigned |
| Равномерный шаг только по проекции | Потеря gantry shear при внешне регулярном стеке | Проверять полные позиции, ортонормальность и согласованность стека; в первой версии отказ от shear/нерегулярности |
| Неопределённые оси и центр/угол вокселя | Зеркальная или сдвинутая поверхность, неверный масштаб STL | Единая формула LPS, x-fastest VTK, MC spacing один раз, компенсация padding и проверка нормалей |
| Tolerance описан без точной формулы | Нельзя доказать, что управление соответствует алгоритму | Выбран локальный перепад HU; тест на градиент отличает его от сравнения с seed. У обоих подходов есть применения; выбранный нужно объяснить |
| Mesh repair сводится к clean/нормалям либо безусловному largest component | Нет реального исправления или потеря отдельных костей | Доказательство заделки дыры и удаления выбранного фрагмента; сохранение исходника; компоненты не удаляются автоматически |
| fill_holes в GUI/QThread под try/except | Native crash закрывает всё приложение | При использовании фильтра — отдельный локальный spawn-процесс, тайм-аут и сохранение предыдущего mesh |
| Быстрое изменение параметров после обработки | Запоздавший mesh или STL относится к старому HU | Версии входов/задач, одна активная тяжёлая задача, инвалидирование downstream, экспорт только актуального mesh |
| Обещание изменения картинки при любом изменении HU | Ложное падение теста на неизменившейся маске | Специальная фикстура с HU между порогами; считать и показывать фактическое число вокселей |
| src-layout без обязательной упаковки | python -m работает только из особой папки/PYTHONPATH | pyproject.toml и editable install на этапе 1; тест запуска из другой папки |
| «Тесты пройдены» по одной синтетике или повторному чтению тем же VTK | Нет доказательства реальной загрузки/GUI/стороннего STL | Два независимых реальных исследования, ручной GUI, внешний редактор, отдельные статусы испытаний |
| Большие CT, очередь задач, Python Region Growing | Перерасход RAM, зависание, усечённая маска | float32, маски валидности, компактный фронт, ограничение очереди, прогресс/отмена и честная ошибка лимита; замерить на реальной машине |

Неопределённости, которые останутся до реальных испытаний: форматы/геометрия файлов преподавателя; скорость на целевом компьютере и видеодрайвере; пригодность алгоритмов обработки на конкретной анатомии. Их нельзя снять только чтением документации. Эти вопросы не блокируют завершение этапа 0.

Проверенные первичные источники и смысл для проекта:

- [DICOM PS3.3, Image Plane Module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.7.6.2.html): IPP — центр первого пикселя, IOP задаёт направления, PixelSpacing — порядок строка/столбец. Основание формулы геометрии.
- [DICOM PS3.3, CT Image Module](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.8.2.html): rescale и условия, при которых выход классического CT определён в HU. Нельзя обобщать на любые CT-derived/multi-energy данные.
- [pydicom: pixel data](https://pydicom.github.io/pydicom/stable/guides/user/working_with_pixel_data.html), [apply_modality_lut](https://pydicom.github.io/pydicom/stable/reference/generated/pydicom.pixels.apply_modality_lut.html): pixel_array декодирует, LUT/rescale — отдельный шаг; без преобразующих тегов LUT возвращает исходный массив. Rescale может вернуть float64, что важно для RAM.
- [pydicom: compressed pixel data](https://pydicom.github.io/pydicom/stable/guides/user/image_data_handlers.html): декодеры зависят от transfer syntax; одного pydicom недостаточно для всех сжатых файлов.
- [scikit-image: marching_cubes](https://scikit-image.org/docs/stable/api/skimage.measure.html#skimage.measure.marching_cubes): spacing соответствует осям массива, результат — треугольники; метод Lewiner допустим для реального MC.
- [PyVistaQt usage](https://qt.pyvista.org/usage.html): QtInteractor в собственном приложении, QApplication/event loop и QT_API для PySide6. BackgroundPlotter сам по себе не обеспечивает отдельный вычислительный поток.
- [PyVista: ImageData](https://docs.pyvista.org/api/core/_autosummary/pyvista.ImageData.html), [add_volume](https://docs.pyvista.org/api/plotting/_autosummary/pyvista.Plotter.add_volume.html): объёмный просмотр и физическая геометрия; OpenGL/драйвер требуют реального GUI-прогона.
- [PyVista: smooth](https://docs.pyvista.org/api/core/_autosummary/pyvista.PolyDataFilters.smooth.html), [decimate_pro](https://docs.pyvista.org/api/core/_autosummary/pyvista.PolyDataFilters.decimate_pro.html): выбранные операции на сетке; доля decimation означает удаление граней.
- [PyVista: fill_holes](https://docs.pyvista.org/api/core/_autosummary/pyvista.PolyDataFilters.fill_holes.html): размер отверстия задаётся радиусом ограничивающей сферы, присутствует предупреждение о segfault. Это реальный риск API, а не гипотетическое требование лабораторной.
- [Qt: QThread](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html): worker-object и сигналы; сцену и виджеты обновляет главный поток.

Онлайн запрашивалась только общедоступная документация и метаданные пакетов. DICOM/сведения пациента в сеть не передавались; DICOM-наборов в проекте нет.
