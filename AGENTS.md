# Инструкции Codex для лабораторной № 5

## Роль и приоритеты

Ты разрабатываешь учебное локальное приложение 3D-реконструкции КТ. Важнее всего корректность обработки DICOM, соответствие заданию и проверяемость. Не делай «красивую, но бутафорскую» демонстрацию.

Источник истины по требованиям: `sources/Лабораторная_5.pdf` и `docs/01_requirements.md`. По методам ориентируйся на `sources/10_3D_реконструкция_по_КТ.pdf` и `docs/04_lecture_notes.md`. При конфликте интерпретации исходное задание выше нашего проектного плана. Другие лекции курса не подменяют лекцию № 10.

Перед программированием прочитай `docs/02_architecture.md`, `docs/03_test_plan.md` и текущую задачу из `docs/05_codex_prompts.md`.

## Работа по этапам

- Не реализуй всё за один проход; закрывай один этап, затем проверяй.
- Не подменяй реальное чтение DICOM тестовыми данными.
- Не объявляй функцию реализованной без проверяемого результата.
- Для каждого этапа: код -> тесты -> ручная проверка GUI, если GUI затронут -> исправления -> короткий отчёт.
- Если нет реального DICOM-набора или нет графической среды, честно укажи, что осталось непроверенным. Не выдумывай прохождение тестов.
- Не начинай следующий этап, пока не отчитался по текущему.

## Технические инварианты

- Данные обрабатываются локально; никакие DICOM-изображения и пациентские сведения не отправляются в сеть.
- По возможности не логируй персональные данные; реальные данные пациентов нельзя коммитить в Git.
- Модель объёма и алгоритмы не должны зависеть от GUI.
- Поддержи обоснованную сортировку срезов по геометрии DICOM, не по имени файла.
- Величины порога применяются к **HU**, не к сырым pixel values.
- `PixelSpacing`, расстояние между срезами и `SliceThickness` — разные понятия; не путай их.
- Не смешивай серии `SeriesInstanceUID` и разные `FrameOfReferenceUID`.
- Если геометрия, HU или декодирование непригодны для корректной реконструкции, выведи объяснение, не придумывай координаты.
- Используй 3D-координаты и физические пропорции последовательно при отрисовке и экспорте.
- В GUI поддержи отсутствие необязательных метатегов (показывай «Нет данных»).
- Долгие вычисления — в рабочих потоках; обновление Qt/VTK-сцены — в главном GUI-потоке.
- Изменение HU действительно пересчитывает маску и результат, а не просто меняет подпись.
- Region Growing использует выбранную пользователем точку и наращивание связной области с регулируемой чувствительностью; не заменяй его обычной глобальной пороговой маской.
- Marching Cubes должен строить настоящую триангулированную поверхность.
- Mesh repair должен реально исправлять обнаруженные дефекты, а не только пересчитывать нормали.
- Изображение, открытое в окне 3D, и экспортируемая сетка должны соответствовать друг другу.

## Код и отчётность

- Создай и поддерживай `requirements.txt` и понятный README для Windows 11.
- Пиши тесты на корректные и ошибочные случаи. Укажи реальные команды и их результаты.
- Не включай в проект backend, DB, FHIR, HL7, U-Net и вход по паролю — это не требуется для лабораторной № 5.
- Добавляй новые зависимости только при объяснимой необходимости.
- Перед завершением изменения перечисли: реализовано; проверено автоматикой; проверено руками; не проверено; известные ограничения.
