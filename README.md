# Лабораторная № 5: 3D-реконструкция КТ — пакет для Codex

Локальное Windows-приложение для загрузки серии CT DICOM, построения HU-объёма, сегментации и 3D-реконструкции. Реализованы обязательная часть и дополнительные задания лабораторной № 5: Region Growing, Marching Cubes, обработка сетки и STL-экспорт.

## Источники и приоритеты

1. `sources/Лабораторная_5.pdf` — **обязательное задание, имеет приоритет в спорных случаях**.
2. `sources/10_3D_реконструкция_по_КТ.pdf` — **лекция № 10**, основной методический источник.
3. `docs/01_requirements.md` — требования, уточнения и границы работы.
4. `docs/02_architecture.md` — архитектура, стек и технические решения.
5. `docs/03_test_plan.md` — критерии приёмки и матрица проверок.
6. `docs/04_lecture_notes.md` — конспект релевантных страниц лекции.
7. `docs/05_codex_prompts.md` — последовательные запросы к Codex.
8. `AGENTS.md` — постоянные инструкции агенту.

Приоритет при аудите: оригинальное задание -> методика лекции № 10 -> техническая корректность и актуальная официальная документация библиотек -> простота реализации и защиты. Проектные документы конкретизируют эти источники, но не меняют их требований.

**Важное различие:** пункты с пометкой «Задание» или «Лекция» прямо следуют из PDF. Пункты с пометкой «Инженерная рекомендация» предложены для повышения качества, но не являются дополнительными формальными условиями преподавателя.

## Реализация

Python 3.12 / PySide6 / pydicom / NumPy / SciPy / scikit-image / PyVista / pyvistaqt / VTK / pytest. GUI на русском. Данные остаются внутри локального процесса; сервер, учётная запись и интернет для работы не нужны.

## Установка на Windows 11

Нужен 64-битный Python 3.12. В PowerShell из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pip check
```

Если команда `python` указывает на другую версию, укажите полный путь к Python 3.12. В проверенном окружении использован CPython 3.12.9 x64.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m ct_reconstruction
```

1. Нажмите «Загрузить папку DICOM…» и выберите каталог исследования.
2. Если найдено несколько CT-серий, выберите нужную. Файлы группируются по SeriesInstanceUID и FrameOfReferenceUID.
3. Проверьте метаданные и spacing. Отсутствующие необязательные поля показываются как «Нет данных».
4. Измените порог HU. Маска пересчитается и появится в 3D; модель вращается, масштабируется и перемещается мышью.
5. Для Region Growing выберите срез, щёлкните seed, задайте допустимый локальный перепад HU и нажмите соответствующую кнопку.
6. Постройте Marching Cubes. Затем доступны сглаживание, упрощение, repair, сброс обработки и STL-экспорт.

STL хранит координаты в миллиметрах в системе DICOM LPS. Формат STL не записывает название единицы измерения, поэтому при импорте выбирайте миллиметры. Экспортируется та же активная сетка, которая показана в окне.

## Тесты

```powershell
$env:QT_API = "pyside6"
$env:QT_QPA_PLATFORM = "offscreen"
.\.venv\Scripts\python.exe -m pytest -q
```

Offscreen-плагин Windows не предоставляет OpenGL-контекст. Поэтому автоматический GUI-тест проверяет создание данных VTK и состояние интерфейса без вызова render. Интерактивный VTK отдельно проверяется обычным видимым запуском.

## Поддерживаемые данные и ограничения

- Основной профиль: классические однокадровые ORIGINAL CT-срезы с IOP, IPP, PixelSpacing, RescaleSlope/Intercept и регулярной ортогональной геометрией.
- Установлены декодеры для распространённых JPEG/JPEG-LS/JPEG 2000 transfer syntaxes; конкретную сжатую серию всё равно нужно проверять.
- Нерегулярный шаг, gantry tilt/shear, отсутствие достоверной геометрии, Enhanced CT/multi-frame и неподтверждённые единицы HU отклоняются с объяснением. Координаты не выдумываются из InstanceNumber или SliceThickness.
- PixelPaddingValue/Range исключается из сегментации. VOI windowing и MONOCHROME1 не меняют численные HU.
- Repair исправляет отверстия до заданного размера; удаление остальных компонент включается пользователем отдельно. Опасный нативный фильтр выполняется в отдельном процессе.
- Реальные данные пациентов и экспортированные модели исключены `.gitignore`; не добавляйте их в репозиторий.
